## 1. Executive Summary & Verdict

`Qwen3-Coder-30B-A3B-Instruct` offers an order-of-magnitude speed improvement over dense models like `Qwen3.8-27B` (achieving **>65 tok/s generation** and **>320 tok/s prompt processing** across 8 concurrent slots). For pure algorithmic synthesis and structured TypeScript code generation, it is significantly faster and creates high-density code in 25–35 seconds that would take 2–3 minutes on dense models.

**However, in an autonomous multi-step agentic loop, it currently exhibits three distinct failure modes:**
1. **Format Confusion:** Tendency to emit markdown code blocks containing pseudo-code (`await write_file({...})`) instead of issuing native JSON function calls.
2. **Scope Overwhelm:** Explicit refusals when prompts frame tasks as large architectural designs rather than atomic implementation steps.
3. **Mathematical Sign Bugs:** Subtle logic mistakes (e.g., negative dot product in closing velocity producing zero collision damage) that slip past syntax checks.

**Verdict:** **Keep using it**, but implement three strict operational guardrails:
1. Ensure `llama-server` is configured with `--jinja` and grammar-constrained tool-call sampling.
2. Structure outer-loop delegation prompts as single-file, atomic directives with explicit mathematical invariants.
3. Always pair code output with an automated contract verification test suite (`@piglet` / `tsx` assertions).

## 2. Chronological Timeline & Failure Analysis

### Phase 1: The Infinite Markdown Loop Bug (Container Misconfiguration)
* **Symptom:** Subagent tasks hung indefinitely, repeatedly generating ````python\n```` in a tight loop.
* **Diagnosis:** Chunkito was running an experimental Docker container (`llama-coder-30b`) on port 11434 with an incompatible chat template / stop token configuration, instead of the canonical `llama-server.service`.
* **Remediation:** Re-pointed port 11434 to the canonical `llama-server` running with 8 slots and proper prompt formatting. Raw generation speed immediately jumped to >65 tok/s.

### Phase 2: Meta-Architectural Refusal (`deleg_8e9c03b3`)
* **Prompt:** Detailed architectural overview quoting Spec 11 and requesting full end-to-end design of NPC competitors and collision physics.
* **Subagent Response:** *"This task involves implementing a complex system with specific technical requirements that are beyond my current capabilities. I can, however, help with individual components or specific aspects of this implementation..."*
* **Root Cause:** Unlike general-purpose reasoning models (Claude 3.5 Sonnet, GPT-4), specialized 30B coder models possess strong conservative guardrails when given multi-subsystem, abstract requests.
* **Lesson:** The Gemini outer loop must perform the architectural decomposition. Never delegate an entire specification; delegate individual modules with pre-scoped interfaces.

### Phase 3: Markdown Hallucination vs. Native Function Calling (`deleg_594a6640` & `deleg_12e19849`)
* **Symptom:** Instead of triggering Hermes's `write_file` tool call schema, the model generated conversational prose and code blocks:
  ```typescript
  // Write the test file
  await write_file({
    path: "tests/verify-collision-and-npc.ts",
    content: `...`
  });
  ```
* **Root Cause:**
  1. **Coder Pretraining Bias:** Coding models are heavily trained on JavaScript/TypeScript snippets where API calls are written as code. When prompted with code context, the model defaults to writing executable scripts inside markdown backticks.
  2. **Jinja / Chat Template Desynchronization:** When `llama-server` exposes an OpenAI-compatible `/v1/chat/completions` endpoint, if tool calls are not grammar-enforced via BNF or strict Jinja templating, the model emits text representations of tool calls.
* **Remediation:** In `deleg_e6f76c91` and `deleg_4dd841dd`, when the prompt was stripped of code snippets and given as a direct imperative command (`Write file X using write_file defining Y`), the model successfully invoked native tool calls.

### Phase 4: Domain Physics Logic Defect Caught by Verification
* **Symptom:** In `RoverCollisionSystem.ts`, collision impulses worked, but zero damage was ever inflicted regardless of impact velocity.
* **Code Generated by Model:**
  ```typescript
  const relativeSpeed = velDelta.dot(normal);
  if (relativeSpeed < 0) {
    const damageA = Math.max(0, relativeSpeed - this.minImpactSpeed) * 0.5;
    ...
  }
  ```
* **The Defect:** When two rovers approach each other along the collision normal, `velDelta.dot(normal)` is negative (e.g. $-7.0$ m/s). Subtracting `minImpactSpeed` ($1.5$) resulted in $-8.5$. `Math.max(0, -8.5)` clamped the damage to `0.0`.
* **Fix Applied:** Changed to `const closingSpeed = Math.abs(relativeSpeed);` and checked `closingSpeed > this.minImpactSpeed`.
* **Lesson:** The model's vector math was conceptually sound (it properly resolved 2D inelastic impulse momentum and collider separation), but sign conventions in dot products require automated verification.
